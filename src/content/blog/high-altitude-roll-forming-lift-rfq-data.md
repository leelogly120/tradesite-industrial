A first enquiry is ready for technical screening when it states the intended roll-forming duty, separates known facts from estimates, identifies the vehicle or crawler assumption, and names the records still to follow. It does not need every final drawing. It does need enough context for a reviewer to say what can be screened now, what must remain conditional, and which missing input prevents a configuration decision. The blank fields below can be copied into an email, tender schedule or controlled RFQ form without using customer data.

## Define the answer the first RFQ should produce

The useful output of an early RFQ is a screening response with a visible evidence boundary. Procurement should be able to tell which architecture is being discussed, which assumptions shape the response, which interfaces are excluded, and what evidence is needed for the next gate. A price without that baseline is difficult to compare because two responses may cover different vehicles, forming modules, site duties or destination responsibilities.

### Write the duty in one sentence

Describe where material starts, where forming is expected to occur, where the panel is handed over, and whether the support concept is crawler-based or truck-mounted. Add the project phase: concept comparison, budget enquiry, technical tender or order clarification. Avoid labels such as “standard,” “heavy duty” or “40HQ model” unless the RFQ defines what those labels include.

A useful duty statement can remain blank and neutral:

> Review a `[crawler / truck-mounted / undecided]` roll-forming lift concept for `[roof or work-zone description]`, using profile record `[document ID / not yet issued]`, with panel handover at `[location / unknown]`. This RFQ is for `[budget screening / technical comparison / tender response]` and does not request site or destination approval.

### Name the requested response

Ask the reviewer to return one of a small number of clearly described outcomes: proceed to configuration review, request a defined missing record, compare an alternate architecture, or hold the affected decision. This is more useful than asking whether the project is simply “possible.” The response should repeat its governing inputs and list exclusions so that a later revision can be compared against the original basis.

### Assign owners before attaching files

Use role names rather than exposing individuals in a public or reusable form. Typical roles may include buyer, roof-system reviewer, site or route owner, chassis integrator, forming-line reviewer, logistics reviewer and local compliance adviser. The contract and destination process determine the actual responsibilities. ARCLIFT may participate as an integrated equipment supplier or technical selection and supply partner; that role does not absorb duties assigned to other reviewers.

## Copy the minimum first-pass RFQ template

Use `Known`, `Estimated` or `Unknown` beside every field. An empty field is not zero, not “standard” and not approval to assume a convenient value. Document IDs may be internal anonymised references; customer names, addresses, vehicle identifiers and sensitive drawings belong only in a controlled project channel.

### Project and decision block

```text
RFQ reference: [blank]
RFQ stage: [concept / budget / tender / order clarification]
Decision requested from supplier: [blank]
Required response date: [blank]
Intended architecture: [crawler / truck-mounted / undecided]
Destination country or rule category: [blank]
Intended movement: [public road / controlled site / mixed / unknown]
Buyer decision owner by role: [blank]
Records that will govern this review: [document IDs and revisions / none yet]
```

The response date is a commercial input, not a promise that unresolved technical work can be completed by that date. If the project is comparing architectures, keep both alternatives visible rather than placing one preferred model in the heading and silently excluding the other.

### Duty, material and work-zone block

```text
Roof or work-zone description: [blank]
Required height and horizontal relationship: [survey reference / estimate / unknown]
Panel handover point and receiving owner: [blank]
Profile drawing ID and revision: [blank]
Material specification owner and record: [blank]
Panel length basis and handling sequence: [blank]
Coil or feed arrangement: [blank]
Power and control boundary: [blank]
Weather and wind-management owner: [blank]
Ground or floor review owner and available records: [blank]
Delivery, access, setup and withdrawal route record: [blank]
```

These are project inputs, not equipment values. A profile name without its controlled drawing does not establish tooling compatibility. A requested height without the roof relationship, handover point and work state does not establish an operating envelope. If data conflict, list both records and ask which one governs.

### Scope and responsibility block

```text
Equipment package expected from supplier: [blank]
Vehicle or chassis included in scope: [yes / no / undecided]
Forming line and tooling included in scope: [blank]
Locally supplied items and services: [blank]
Destination integration owner: [blank]
Site route and work-zone owner: [blank]
Packing or transport study required: [yes / no / undecided]
Requested document language and format: [blank]
Known exclusions: [blank]
Open decisions that must not be assumed: [blank]
```

Scope words should describe supply boundaries, not imply that an item is available. If the buyer expects a calculation, drawing, certificate, manual or test record, enter it in a proposed deliverable register and request an availability response. The separate [technical document package guide](/blog/roll-forming-lift-technical-document-package/) explains that later procurement task.

## Add records only when the review reaches them

The first pass should be short enough to complete, then expand by decision gate. Use this task-specific attachment checklist to show what exists and what is still due:

- Attach the current roof or work-zone survey reference for **height**, outreach relationship and handover geometry; mark estimates visibly.
- Add the controlled panel **profile**, material and length records only when forming compatibility is under review.
- Identify the **coil** or feed arrangement and its owner without inventing handling limits or a lifting method.
- Reference the site **wind** and weather responsibility record; do not insert a generic operating threshold.
- Name the competent owner of **ground or floor** review and list the records that are available, pending or not yet commissioned.
- Map delivery, **access and route** states only to the level needed for the architecture decision.
- State whether **transport or chassis** supply is included, excluded or undecided and name the destination integrator if appointed.
- Record available **voltage, power and control** information as project inputs, with revision and owner.
- List destination documentation or local **compliance requirements** as questions for the appointed reviewer, not supplier declarations.
- Link every open item to the decision it holds and the evidence expected to close it.

### Keep a compact input register

For each attachment record its ID, title, revision, status, owner role and purpose in the RFQ. Do not use a filename as the only identifier. The register lets reviewers detect when a route plan, profile drawing or scope schedule changes after a budget response has been issued.

### Use an open-item disposition

Every gap should show its consequence. Write `needed before architecture screen`, `needed before configuration response`, `needed before commercial scope can be firm`, or `outside this supplier review`. Avoid “TBC later” without a decision owner and gate. Closing an item means recording the new evidence and checking whether it changes previous assumptions.

### Freeze the response basis

Ask the reviewer to return the input-register revision used, explicit assumptions, exclusions and open items with the response. This snapshot does not prove the inputs correct. It makes the commercial comparison traceable and prevents a later attachment from silently changing the basis of selection.

## Route missing data without false precision

Early procurement often has incomplete site and equipment information. The useful trade-off is not “fast versus accurate”; it is choosing a response whose certainty matches the available evidence. A budget screen may proceed with named assumptions, while a configuration or contractual commitment may require controlled records. Missing information should narrow the response rather than invite copied values from another model or project.

### Match the gap to the response

- **Architecture still undecided:** compare the data needed for crawler and truck routes; do not present the result as a model recommendation.
- **Profile or material record not controlled:** hold tooling compatibility and request the governing record; do not confirm a standard line.
- **Height or handover geometry estimated:** keep the work envelope preliminary; do not imply approved reach or suitability.
- **Chassis scope undecided:** split equipment-module and vehicle-interface questions; do not imply complete vehicle supply.
- **Ground, floor or route review has no owner:** hold the affected site decision; do not treat an RFQ reply as site acceptance.
- **Destination requirements unknown:** route them to the appointed local reviewer; do not treat supplier commentary as compliance confirmation.

### Compare replies by decision coverage

Check whether each reply repeats the same scope, distinguishes included and locally supplied items, identifies assumptions, lists requested deliverables and routes open questions to named roles. Do not compare only the headline price. A lower price may simply omit chassis integration, tooling, packing, local services or document scope that another response includes.

For general planning context, the <a href="https://www.hse.gov.uk/pubns/geis6.htm" target="_blank" rel="noopener noreferrer">HSE GEIS6 page on selecting and managing mobile elevating work platforms</a> discusses task- and site-based selection in its own UK MEWP scope. It does not classify this equipment, verify an ARCLIFT configuration or settle destination requirements.

### Stop when the RFQ cannot support the decision

This template may not fit a project that cannot define the intended duty, provide a controlled route for sensitive records, or appoint owners for structural, vehicle, site and destination decisions. An RFQ cannot establish equipment fit, roof adequacy, route authorization, road legality, a lifting method or site acceptance. When a governing profile, work-zone relationship, carrier concept or supply boundary is unknown, keep that decision on hold instead of converting the blank into an assumed value.

### Request a bounded screening response

Send the completed RFQ template, anonymised input register and only the records needed for the current decision through a controlled project channel. Ask ARCLIFT, as an integrated equipment supplier and technical selection and supply partner, to return the governing assumptions, exclusions, missing inputs and next review gate. Site height, work-zone geometry, ground or floor evidence, transport or chassis scope and destination questions remain with the named project reviewers. A final, signed, project-specific package is still required for committed scope and approvals. Every editorial image on this page remains a planning aid, not configuration or performance evidence.

## FAQ

#### What is the minimum information for a first RFQ?

Provide the requested decision, project stage, intended duty, architecture assumption, destination category, work-zone relationship, profile-record status, supply boundary and owner of each unresolved interface. Mark unknown items openly rather than estimating them without a source.

#### Can procurement send this template before the site survey is complete?

Yes, for a bounded screen if the missing survey is identified and the reply is requested on an assumption-led basis. The resulting response must keep the affected work-zone, route and configuration decisions preliminary.

#### Should a preferred model appear in the RFQ?

It may appear as a comparison reference, provided the RFQ explains why and allows the reviewer to identify conflicts or alternatives. A reference label is not evidence of current configuration, availability or project fit.

#### How should suppliers respond to an unknown field?

They should state whether the field blocks the present decision, can remain an explicit assumption for a limited screen, or belongs to another appointed reviewer. The reply should identify the record needed to close it.

#### When does the RFQ become a controlled contract input?

Only through the project’s agreed process. Procurement should identify which RFQ revision, clarifications, signed technical schedule and exclusions form the contractual baseline; this public blank template does not do that by itself.
